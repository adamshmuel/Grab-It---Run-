# V1 — מפת הגדרות המשחק

**מצב, 25/10/2026: המימוש המקורי אינו עומד במטרות; אדם אישר את חבילת השיפורים וביקש היתכנות ולאחריה קידוד, עם עצירה לפני בדיקות הקבלה.**

אדם אישר gameplay ב־21/10 והגדרות V1 ובנייה ב־22/10/2026, כולל מחשב ונייד. לאחר בדיקות טכניות והשוואה חזותית מוגבלת, הבדיקה הידנית חשפה כשלים בחוויה. [אבחון הכשל](../../research/v1-design-failure-review.md) נשמר, וההגדרות החדשות אינן מסמנות את המימוש הישן כהצלחה.

## מקצה השיפורים — נקודת הכניסה לקריאה

[מפת שיפורי V1 והכיסוי לשבעת הסעיפים](improvements.md) היא המסמך המקשר. ממנה עוברים לנשיאה, לשלבים ודירוג, לקטלוג, לסביבה, לעיצובים, ל־Controls ולשמירה. [תנאי קבלת השיפורים](improvement-acceptance.md) מחייבים רצף מעבר להישג הראשון, מיצוי תוכן, השוואה לרפרנסים והוכחה נפרדת לחוויה אנושית.

הגרסה המתוקנת כוללת מחסן אחד, שלושה שלבים בזמנים מתקצרים, 30 רגילים מחמישה סוגים בכל שלב ועוד מיוחד בשלב 3, קיבולת משקל, דירוג חי ומשותף, תגמול אישי, עיצובים לקנייה במטבעות המשחק ושמירה. עד שמונה שחקנים, מחשב ונייד מדומה עם touch. אין יתרון לעיצוב שנקנה. ההגדרות המפורטות, ולא התקציר, מחזיקות את המספרים והחריגים.

אין פרסום לציבור, Robux, כסף אמיתי, gamepad, VR, PvP, גניבה, מסחר, מפות נוספות, שדרוגי קיבולת שמורים, משימות יומיות או לוח דירוג עולמי. לוח השלבים המקומי ורכישות במטבעות המשחק נכללים במקצה החדש; הוצאתם ההיסטורית מהבסיס אינה חלה עליו.

## קשר למטרות והראיות

[מטרות הפרויקט](../project-goals.md) נשארות המסגרת: כניסה פשוטה ומהירה, איכות מתחרים, סיבה לחזור, מוצר בר־תחזוקה ואפשרות לשימוש חוזר בעתיד. משקל, מסעות, תוכן, רכישה ומעברים נותנים ביטוי קונקרטי למטרות, אך אינם מוכיחים אותן.

[דוח הבדיקות הקודם](../../research/v1-validation.md), [מפת המוכנות](../../research/project-readiness.md) ו[מצב הקבלה](../../research/v1-acceptance-status.md) שומרים את תוצאות הבסיס ומגבלותיהן. השיפורים טרם נבנו או נבדקו ב־Studio. תוצאות ישנות אינן מכסות את השינויים. הכנסה, retention ארוך ותמיכה בחומרת נייד פיזית אינם מוכחים.

## SDD והמשך

אדם אישר את החבילה בתאריך 25/10/2026 וביקש בדיקות היתכנות ולאחריהן קידוד. לאחר ההיתכנות נכתבות תוכניות מתאימות; התוכניות הקודמות נשמרות כתיעוד הבסיס. TDD וכן code review הם חלק מהפיתוח. לפני שלב בדיקות הקבלה עוצרים ומודיעים לאדם כדי שיוכל להעלות את חוזק המודל. אין אישור לפרסום או הזמנת שחקנים. קומיטים מקומיים לעבודה המאושרת מותרים; אדם בלבד מבצע push.
