## במחשב הנוכחי, לפני המעבר

1. **לדחוף את branch העבודה.** לאחר קומיטי ההעברה, אדם מבצע push של `codex/v1-improvements` אל origin ומוודא שהוא מופיע ב־GitHub. השיחה אינה מבצעת push.
2. **לוודא שקומיט הגיבוי נדחף.** הרפרנסים ועותק הגיבוי הידני מגיעים כעת דרך Git. [רשימת הקבצים והחתימות](local-files.json) מאפשרת לוודא שהם הגיעו שלמים. אין צורך להעתיק את שתי השמירות שבשורש בנפרד.
3. **לשמור את המחשב הישן עד שההעברה אומתה.** קובצי הגיבוי לא נפתחו במהלך הבדיקה, ולכן לא נקבע שהתוכן הידני שלהם זהה לתוכן קובץ העבודה. שמירה לענן אינה מחליפה את העברת המקורות והרפרנסים.

עותק הגיבוי שנכלל ב־Git:

`backups/manual/2026-10-26/GrabItV1_DesktopMobile.rbxl`

[תיעוד הגיבוי](../../backups/README.md) מפרט את מקורו ואת מגבלות השימוש בו. אין לפתוח אותו במקום קובץ העבודה בדרך רגילה.

`sourcemap.json` הוא קובץ מיפוי שנוצר מקומית. אינו מקור הקוד ואינו נדרש להעברה. קובצי `.DS_Store`, שרתי תצוגה, תהליכים ומצב חיבור אינם הגדרות פרויקט להעברה.

## במחשב החדש — צעדים לפי הסדר

1. **להתקין Git ולהתחבר ל־GitHub.** לבחור Mac או Windows מתוך [אתר Git](https://git-scm.com/install/). לוודא שלחשבון יש גישה למאגר. אפשר לבצע clone דרך ממשק Git קיים; התחברות לחשבון אינה עוברת יחד עם התיקייה.
2. **להוריד דווקא את branch העבודה.** לבצע clone של המאגר ולבחור `codex/v1-improvements`. אפשר לבחור שם תיקייה פשוט כמו GrabItRun; אין דרישה לשחזר את נתיב המשתמש מהמחשב הישן. [הוראות clone הרשמיות](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository) מסבירות גם שימוש בממשק גרפי.
3. **לוודא שהחומר הגיע.** לבדוק שתיקיית references וקובץ הגיבוי המתועד קיימים אחרי המשיכה. אין צורך בשתי השמירות המקוריות שבשורש המחשב הישן. לא להחליף את קובץ build בגיבוי; הוא מיועד לשחזור בלבד.
4. **להתקין את אפליקציית OpenAI שבה תעבוד.** להיכנס לאותו חשבון ולפתוח את תיקיית הפרויקט במצב Codex. להשתמש ב[הוראות האפליקציה הרשמיות](https://learn.chatgpt.com/docs/app). לתת גישה לתיקיית הפרויקט, ולוודא שנקראו AGENTS ו־rules ושהמיומנויות המקומיות מופיעות. לפי [תיעוד המיומנויות](https://learn.chatgpt.com/docs/build-skills), Codex סורק את `.agents/skills` מתוך המאגר. אין צורך להתקין את 14 המיומנויות שוב ברמת המשתמש.
5. **להתקין Roblox Studio.** להוריד מתוך [ההוראות הרשמיות](https://create.roblox.com/docs/studio/setup) ולהיכנס לאותו חשבון Roblox. בשלב ההכנה אין צורך להפעיל משחק. האימות של החיבור והסנכרון בהמשך ייעשה רק כשהפרויקט הזה הוא יעד העבודה המורשה.
6. **להתקין Rokit.** לבחור את הוראות Mac או Windows בתוך [המאגר הרשמי](https://github.com/rojo-rbx/rokit#installation), ואז לפתוח Terminal חדש. מתוך תיקיית הפרויקט להריץ rokit install. הקובץ rokit.toml יקבע את הגרסאות: Rojo מספר 7.7.1, StyLua מספר 2.5.2 ו־Selene מספר 0.32.0. אין להריץ rokit update או rokit init לצורך המעבר; אין צורך לשנות את הגרסאות.
7. **להתקין את Rojo plugin.** אחרי התקנת Studio והכלים, להריץ rojo plugin install מתוך תיקיית הפרויקט, או להתקין את plugin הרשמי התואם ל־Rojo 7. ה־CLI וה־plugin הם שני רכיבים נפרדים, לפי [הוראות Rojo](https://rojo.space/docs/v7/getting-started/installation/). התקנת plugin אינה הפעלת שרת סנכרון.
8. **להגדיר מחדש את Studio MCP.** כשהעבודה במשחק הזה תחודש, לפתוח רק את קובץ העבודה שלו בחלון Studio אחד. ב־Assistant לפתוח Manage MCP Servers, להפעיל Enable Studio as MCP server ולבחור את לקוח Codex בתוך Quick connect. אם הוא אינו מופיע, לפעול לפי Setup instructions ולא להעתיק נתיב Mac למחשב Windows. נדרש חיווי של לקוח מחובר; מתג מסומן לבדו אינו מספיק. [הוראות MCP הרשמיות](https://create.roblox.com/docs/studio/mcp).
9. **לבצע אימות קצר לפני המשך הפיתוח.** לבקש מהשיחה החדשה לקרוא תחילה את מסמך המעבר ואת נקודת העצירה. לוודא שזהות המשחק היא place מספר 106986292768692 ו־universe מספר 10772701508, ושמבנה הפרויקט תואם. לא להשתמש במשחק אחר לצורך בדיקת החיבור. לאחר אישור חידוש העבודה מפעילים שרת Rojo אחד בפורט 34872, מחברים אליו את החלון הנכון ומאמתים שהקוד העדכני מתוך src הגיע אליו לפני Play. לא יוצרים מקום חדש ולא מריצים build מעל קובץ העבודה.
10. **להמשיך מנקודת העצירה.** שער התצוגה ויתר הקבלה עדיין לא הסתיימו. כלי QA ההיסטוריים מחייבים התאמה לפני שימוש, כמפורט בנקודת העצירה. בכל עצירה מכבים את שרת Rojo של הפרויקט ומאמתים שהוא נסגר.

## פקודות לשימוש בזמן ההעברה בלבד

כל קבוצה מיועדת למחשב המצוין מעליה. אין להריץ את כולן ברצף במחשב אחד. פקודות התקנת Rokit תלויות במערכת ההפעלה ונמצאות בקישור בשלב 6. הפקודות שלהלן לא הופעלו במסגרת הכנת המסמך.

```sh
# Current computer: run from the existing repository; Adam pushes.
git push --set-upstream origin codex/v1-improvements

# New computer: run from the parent folder chosen for the project.
git clone --branch codex/v1-improvements https://github.com/adamshmuel/Grab-It---Run-.git GrabItRun
cd GrabItRun
git branch --show-current
git log -1 --oneline

# New computer: after installing Studio and Rokit.
rokit install
rojo --version
stylua --version
selene --version
rojo plugin install

# Only after authorized resumption in the verified game window.
rojo serve default.project.json --port 34872
```

אין חובה להתקין כרגע VS Code, Node.js, Python, Wally או JestRobloxRunner כדי להפעיל את קוד המשחק והבדיקות המקומיות הקיימות. קובצי הבדיקה משתמשים ב־assertions בתוך Studio; ה־hook המיובא אינו פעיל. אם עבודה עתידית תדרוש כלי נוסף, מאמתים צורך ותאימות לפני התקנתו. לקריאת המסמכים אפשר לפתוח את קובצי HTML השמורים בתוך docs/previews בדפדפן, גם בלי שרת localhost הישן.

## הגדרות שנשארות ברמת המחשב

חיבור MCP המקומי הקיים מפנה לקובץ StudioMCP בתוך התקנת Studio במחשב Mac. אין להעתיק את כל הגדרות המשתמש של Codex או נתיבי יישומים למחשב השני. רושמים מחדש את חיבור Studio לפי מערכת ההפעלה. [תיעוד ההגדרות של OpenAI](https://learn.chatgpt.com/docs/config-file/config-basic) מבדיל בין הגדרות משתמש לבין הגדרות פרויקט.

התחברות לחשבונות, אישורי מערכת, בחירת מודל, הגדרות אפליקציה וחיבורים של plugins חיצוניים אינם חלק מ־Git. מאמתים אותם במחשב החדש לפי הצורך. אין להעביר סיסמאות או מפתחות פרטיים אל המאגר. אין צורך בהרשאות שליטה כללית במחשב לשם פעולות Studio שה־MCP מספק. אישור API Services הקודם מוגבל למשחק הזה; אינו היתר לשנות סביבה או נתונים של משחק אחר.

## מתי ההעברה הושלמה

- branch העבודה וכל קומיטי ההעברה הגיעו למחשב החדש; החוקים, 14 המיומנויות וקובץ העבודה קיימים.
- עותק הגיבוי המתועד והרפרנסים הגיעו באמצעות Git ונבדקו מול החתימות. התמונות נפתחות מתוך מסמכי המחקר. שני המקוריים בשורש אינם נדרשים במחשב החדש.
- הכלים נמצאו בגרסאות המוגדרות, והאפליקציה קוראת את הוראות הפרויקט.
- בחידוש המורשה אומתו זהות המשחק, חיבור MCP וסנכרון Rojo בפועל. עד אז הסביבה החדשה מוכנה להתקנה, אך אינה סביבה שעברה אימות הרצה.
