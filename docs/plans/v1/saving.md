## סדר העבודה

tests עם storage מוזרק: כישלון טעינה, בעלות על session, שמירה חוזרת, אישור ישן וטעינה מחדש. UpdateAsync עם נעילת session, תור כתיבה והגבלת זמן. בדיקות מקומיות משתמשות ב־storage בזיכרון שמסומן ככזה; אין הפעלת API Services או פרסום ללא אישור.

בכל התנהגות: test נכשל → שינוי מינימלי שעובר → cleanup ו־code review. תוצאות נרשמות בדוח המימוש; לא מסמנים את הגרסה כמתקבלת על בסיס כתיבת קוד בלבד.

## מצב נוכחי

## בדיקת ענן מורשית — 24/10/2026

אדם שמר את המשחק לענן ואישר הפעלת גישת API מתוך Studio עבור המשחק הזה בלבד. היעד אומת: PlaceId הוא 106986292768692 ו־GameId הוא 10772701508. נדרשת בדיקה דרך מסלול המשחק עצמו, עם DataStore נפרד ל־QA ושני שרתי Solo עוקבים באותו חלון.

תחילה test נכשל לבחירת סביבת השמירה: משחק חי משתמש בשם הייצור הקבוע ומתעלם ממאפייני בדיקה; Studio רגיל משתמש בזיכרון; רק סימון זמני ותקין בתוך ServerStorage מאפשר את שם ה־QA הקבוע ואת מפתח ההרצה הייחודי. Client אינו יכול לקבוע את הסימון. שמות הייצור אינם ניתנים לבחירה דרך נתוני QA.

לאחר השינוי המינימלי נבדקים: שחקן חדש, הפקדה ו־Saved אמיתי, פתיחת Copper, session מתחרה שנדחה, סיום שרת ושחרור הנעילה, ואז שרת חדש שטוען את אותה יתרה ומראה בלי מטען. קריאות האימות משתמשות ב־UseCache=false. בסיום מסירים רק את מפתח הנתונים שנוצר להרצה, משחזרים את הסימון הזמני ומוודאים חלון אחד. אין פרסום גרסה חדשה או שינוי לגישה הציבורית.
