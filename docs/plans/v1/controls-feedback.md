# תוכנית מימוש: קלט וממשק

**הרשאה: אדם אישר את הגדרות V1 וביקש להתחיל לבנות בתאריך 22/10/2026.**

מסמך המקור: [הגדרות התחום](../../specs/v1/controls-feedback.md).

## סדר העבודה

tests לחוזה נתוני HUD ולבחירת חפץ קרוב. קלט מקלדת ו־touch מפעילים אותה בקשה. בדיקת תצוגה, אזהרות, הדרכה ומצלמה; שמירת פערי בדיקת הדמיית נייד כאשר לא אומתו.

בכל התנהגות: test נכשל → שינוי מינימלי שעובר → cleanup ו־code review. תוצאות נרשמות בדוח המימוש; לא מסמנים את הגרסה כמתקבלת על בסיס כתיבת קוד בלבד.

## מצב נוכחי

נכתב מימוש ראשוני ותועדו הבדיקות בתוך [דוח המימוש](../../research/v1-implementation.md). אין סימון קבלה מלאה; הפערים הרשומים בדוח עדיין פתוחים.

בתאריך 22/10/2026 הושלם גם סימון החפץ הנבחר ותוקנה חפיפת ההדרכה לכפתור בנייד, לאחר tests שנכשלו לפני השינויים. נבדקו במשחק מעבר סימון, איסוף, הפקדה ותצוגת נייד. נותרו בדיקות כל זוויות המצלמה, מחוות touch במקביל, יתר גדלי המסך והתגובות לאורך session מלא.

## תיקון מצלמה ליד קיר — 24/10/2026

גרירת touch ליד הקיר הימני חשפה כיווץ של המצלמה ל־1.609 studs, מתחת לטווח המאושר 8–20. בדיקת מרחק המצלמה נכשלה באותה סצנה לפני השינוי. משתמשים במצב Invisicam המובנה דרך הגדרות StarterPlayer של הגדרות Rojo של המשחק ושל release; פרויקט tests אינו מייצר דמות. בשרת חדש חוזרים לאותו מקום ואותה זווית, בודקים שהמרחק אינו קטן מהמינימום ושומרים צילום חדש. בודקים גם בסיס, מחסן ומטען; אין שינוי collision או קוד מסונכרן ב־Studio.

בדיקת הצילום לאחר החלפת מצב המצלמה חשפה שלוחות הקיר והמדפים הדקורטיביים עדיין הסתירו את הדמות: הם לא השתתפו בשאילתות המצלמה. test חדש נדרש ללוח קיר שאפשר לזהות כמכשול מצלמה, ובדיקת ray מהשחקן לחפץ מוודאת ששינוי זה אינו חוסם איסוף. רק פרטים מבניים אטומים משתתפים בשאילתה; פסי רצפה וקישוטים קטנים נשארים מחוץ לה. דרישת ה־test הישנה שלפיה כל פרט דקורטיבי אינו ניתן לשאילתה הוחלפה בדרישת ההתנהגות המעודכנת לפני שינוי המימוש.

## חלונית דירוג קריאה — אישור אדם, 26/10/2026

הסיבה: בדיקת שמונה שורות בלוח הקיר נכשלה בנייד. אדם אישר Scores לצד Styles. היתכנות פתיחה במחשב ובמגע ושימור השעון תועדה בדוח הבדיקה; סגירה במגע נדרשת במימוש.

1. test נכשל לפתיחה במהלך שלב, שמונה שורות, עדכון הפקדה, סגירה ומעבר לתוצאות. test פריסה במידות הקבלה, בלי לחפוף לכפתור Close.
2. מודול Scores מקומי המשתמש בטבלה ובמילוי הנתונים של Results; אין remote חדש או חישוב ניקוד מקומי. כפתור ב־HUD ופתיחה בלעדית מול Styles.
3. בדיקת משחק אמיתית לפתיחה וסגירה במחשב ובמגע, שעון ממשיך, הפקדה חיה ומעבר שלב. מדידה וצילום בכל מידות הקבלה.
4. code review, ניקוי תוצרי הבדיקה ועדכון ראיות; חזרה לשער ההשוואה החזותית לפני קבלה רחבה.

## הודעת אובדן בתוצאות — 26/10/2026

בהרצת חידוש העבודה אומת שמסך התוצאות מסתיר את ההודעה הקיימת. ההבהרה נמצאת בכלל 3 במסמך ההגדרות.

1. test נכשל להודעת אובדן בתוצאות ובסיכום, עם שמונה שורות ובארבע מידות הקבלה. לבדוק קריאות, היעדר חפיפה והסרת ההודעה עם סיום משכה.
2. להעביר את הודעת האובדן הפעילה אל מידע ההמשך במסך Results. לשמור את משך ההודעה הקיים ואת הטקסט ללא סכום; אין שינוי שרת או ערוץ רשת.
3. לאמת מעבר אמיתי לאחר איסוף ותום זמן, לשמור ראיות לפני ואחרי, לבצע code review ולחזור לשער התצוגה. אין שימוש בכלי QA ההיסטוריים בשלב זה.

## מניעת כיסוי תוצאות בידי בקרי נייד — 26/10/2026

תצוגת שמונה שורות ב־Samsung חשפה joystick מעל השורות התחתונות; בדגימות מעבר אמיתי הבקרים נשארו פעילים בתוצאות. התיעוד הרשמי מאשר שליטה דרך GuiService.TouchControlsEnabled.

להרחיב את Hud.spec הקיים: כשל לפני התיקון להסתרה בתוצאות ובסיכום, החזרה בשלב פעיל ושחזור בעת סגירת הממשק. לתקן בתוך Hud הקיים בלבד, בלי מודול או כלי בדיקה חדש. לאמת את הבקרים במעבר אמיתי ואת שמונה השורות בהדמיה, ולשמור את ההבחנה בין שורות מדומות למשתתפים אמיתיים.

## שמירת תנועה וקריאת Scores בנייד — 26/10/2026

אחיזה ב־joystick במהלך Scores חשפה חפיפה לשורות 7 ו־8. הבקר הפעיל שנמדד מגיע עד כ־108 פיקסלים משמאל; בדיקת הפריסה תשאיר אזור של 130 פיקסלים ליד השורות התחתונות. הטקסט נשאר בגודל 18 והשורות בגובה 26 לפחות.

להרחיב את ScoresLayout.spec הקיים בבדיקה נכשלת לאזור הבקר בשני המסכים הנמוכים. להזיז את טבלת Scores ימינה ולצמצם את רוחבה רק במסך נמוך, תוך שמירת כל הנתונים ו־Close. אין שינוי בפריסת התוצאות, ערוצי רשת או תנועה. לאמת שמונה שורות מדומות בתוך החלונית האמיתית, קלט מגע פעיל, קריאות, סגירה וגדלי המחשב.

בדיקת המראה חשפה צפיפות בין Unranked לשם גם כשהטקסט התאים. בדיקת ריווח נוספת נכשלה. הפריסה הסופית משתמשת במלוא הרוחב שנותר מימין לאזור הבקר, ו־Close נמצא בשטח הפנוי משמאל למעלה במסך נמוך. נשמר מרווח טקסט של 8 פיקסלים לפחות מעבר לרוחב Unranked; אין צמצום של הטקסט או של השורות.
