מקור: ההגדרה המאושרת. אדם אישר את ההגדרות וביקש קידוד בתאריך 25/10/2026.

במהלך קידוד מריצים TDD, בדיקות עיצוב וניתוח וכן code review. בתום המימוש מתעדים פערים ומצב ומפסיקים לפני בדיקות הקבלה. השוואת מתחרים וחוויה קודמת לשאר בדיקות הקבלה לאחר חידוש בידי אדם.

הסיום כאן הוא מימוש ובדיקות פיתוח, לא אישור קבלה או הוכחת הנאה. אין פרסום או הזמנת שחקנים.

חידוש כלי QA אחרי שער התצוגה

אדם חידש עבודה והשער העצמאי הושלם ב־26/10/2026. מתאימים את launch, server ו־client הקיימים, בלי runner מקביל: סימון גרסה מפורש, הגבלת 1–8 שחקנים וזמן 0–900, החרגת בדיקות פריסת לקוח מהשרת, וקטלוג לפי השלב הנוכחי. מסע ראשון מאמת שמונה פריטים במשקל 10, תגמול 18 והאטה לפי משקל; מצב smoke משתמש בברווז אחד. ההמשך מאמת אובדן בתום שלב והפקדה בשלב הבא, ועומס ממשיך דרך שלבים וסיכום בלי להסתמך על חמשת המקומות הישנים.

בודקים תחילה כשל על הנחות הבסיס הישנות בבדיקה קיימת או בדיקת חוזה ממוקדת, ואז שינוי מינימלי ובדיקת Solo קצרה לפני שניים ושמונה clients. מסעות האיזון נמדדים לפי נקודות המסלול המחושב, הליכה רגילה ושעון שרת, עם יומן פריטים, משקל, תגמול והפקדה. אין הסרת guard בלבד, שינוי קבועי המשחק או הסקת קבלה ממסלול smoke. שמירה בענן דורשת זהות משחק מאומתת; הקובץ המקומי בעל מזהים 0 אינו מספיק.

מצב RoutePlan אופציונלי משתמש באותו client ובאותו walk, בלי runner נוסף. מעבירים את שלוש רשימות המסעות מקובץ חישוב האיזון; נשמר יומן הפקדות לפי זמן השרת, נבדקים רפי 30/18/15, מעבר יחיד מוקדם ומקצה חדש. שומרים על גישה למיוחד מהרצפה במרחק 4, ללא קפיצה. משך ההרצה מוגבל ל־450–900 שניות.

בבדיקות השמירה המבודדות הקיימות משלימים חיוב ליתרת אפס לכל שלושת המחירים, חזרה על אותו מזהה עסקה וטעינה אחרי שחרור נעילה. אלה בדיקות מול backend מדומה; הן אינן מחליפות ענן או רכישה מיתרה שהורווחה ב־gameplay.

בסיום מסעות המקצה, לאחר שימור היתרה במקצה חדש, בודקים דרך remotes רגילים קנייה מתוך המטבעות שהורווחו: ניסיון בחירה לפני בעלות, קנייה כפולה, חיוב יחיד, בחירה לאחר אישור והיעדר יתרון מהירות; מחיר שאינו בהישג היתרה נדחה בלי חיוב. אין זיכוי מלאכותי לשחקן, ואין טענה שכך נרכשו כל העיצובים.

לכיסוי הצטרפות בזמן שלב שהתחיל ביחיד מוסיפים מצב staggered באותו launcher: מתחילים client אחד, ממתינים לאישור active ואז AddPlayers עד שמונה. מאמתים שהמצב והזמן אינם מתאפסים, המצטרפים Unranked בשלב הנוכחי, ובשלב הבא כולם מדורגים והמצב multi. נשמרים הגבולות והיציאה המסודרת בסיום.

מדידת ביצועים משתמשת בספירת RenderStepped הקיימת. מתחילים את חלון המדידה רק אחרי אימות client נבחר, viewport וגרפיקה, וממתינים ל־600 שניות מדודות גם אם ההפעלה החלה מוקדם יותר. ה־watchdog נשאר מוגבל. תוצאות חלונות רקע נשמרות בנפרד; בדיקה מהירה או רזולוציה אחרת אינה עוברת את הרף.

לכיסוי מיצוי עיצובים מוסיפים לאותו RoutePlan אפשרות finishCosmetics: שתי השלמות מקצה ואיסוף נוסף מוגבל בשלישי מתוך המשחק עצמו, עד שאפשר לרכוש גם Royal. לא מזרימים מטבעות ולא משנים זמנים. המסעות הראשונים ממשיכים לעמוד ברפי האיזון; הסיבוב החלקי השלישי מסומן כהמשך צבירה ואינו ראיית רף. אחרי שכל העיצובים בבעלות, בודקים איסוף והפקדה נוספים ללא יתרון כוח. ההרצה מוגבלת ל־900 שניות ועוד watchdog קיים; אין לטעון להשלמה אם הזמן נגמר.

כדי לשמור את client קריא, מסעות ורכישות מרוכזים במודול QA יחיד routes, שמקבל את פונקציות ההליכה והאיסוף הקיימות. אין מימוש נוסף שלהן או framework. המודול משוכפל לערוץ הזמני רק בהרצת מסעות ונמחק עמו בסיום.

אימות ענן כאשר קובץ העבודה מקומי

הקובץ המקומי מדווח על מזהים 0. לצורך הבדיקה בלבד ניתן לפתוח חלון זמני של המשחק המאושר: place מספר 106986292768692 ו־universe מספר 10772701508, לפי Studio CLI הרשמי. לפני הפתיחה מכבים Rojo; לפני כל שינוי מאמתים מזהים, מבנה ומקורות. קובץ העבודה נשמר במקומו, בלי דריסה או פרסום. בסיום מנקים את סביבת QA הזמנית וסוגרים רק את החלון שנוצר וזוהה.

אין לשנות הרשאות או נתוני production. אם שמירה אוטומטית עלולה לשמור סימון QA ב־Edit, לא מוסיפים אותו שם. במקרה זה אפשר לבדוק את מודול Persistence העדכני ב־Play מול DataStore הנפרד GrabItV1_QA_Verification ומפתחות הרצה חדשים בלבד, ולהשאיר חיבור שחקן מלא כפער אם לא הושלם. מוודאים שכל מפתח חדש אינו קיים לפני הבדיקה, ומוחקים ומאמתים מחיקה בסופה. בדיקת backend בענן אינה מוצגת כהוכחת UI או חיבור שחקן מחדש.

אימות הענן הישן נכשל על schema מספר 1 מול רשומה חדשה בגרסה 2. מעדכנים את cloud-check הקיים לגרסה 2 ולבדיקת בעלות ובחירה אופציונלית, ומשתמשים באותו קוד מקומי כפקודת בדיקה לקריאה בלבד ב־Play; אין עריכת Source בענן. שני שרתי Play עוקבים יטענו את אותם מפתחות QA, יבדקו אפס ובעלות, ישחררו נעילות, ולבסוף יימחקו המפתחות החדשים בלבד.

באותו backend QA מבודד בודקים גם תגובה שהוסתרה בכוונה אחרי UpdateAsync שהתחייב בענן: הקורא נשאר pending, ניסיון חוזר באותה עסקה מאשר חיוב יחיד, ושינוי יתרה מקביל בזיכרון מתמזג בלי אובדן. זו הזרקת תקלה מבוקרת בתשובה, לא תקלה אמיתית ברשת ולא הפקדה דרך UI. מאמתים נעילה מול בעלים אחר ושחרור לפני ניקוי.

כלי בדיקה בלבד. המקורות נמצאים כאן; Rojo מציב את התבניות בתוך ServerStorage.GrabItQA, שם הן אינן מופעלות. אין לערוך את המקור דרך Studio.

מצב 26/10/2026: לאחר חידוש העבודה ומעבר שער התצוגה הותאמו הכלים לקטלוג, למשקל ולשלבים. סימון הגרסה הוא GrabItV1.ImprovementsQA; launch מסרב לתבניות מהבסיס הישן. בדיקות פריסת הלקוח אינן רצות בשרת. תוצאות ומגבלות כל הרצה נרשמות בדוח הבדיקה; עצם עדכון הכלים אינו קבלה.

הפעלה בטוחה

מפעילים רק מתוך Edit בקובץ הפרויקט המאומת, דרך Studio MCP. יוצרים עותק זמני של מודול launch, טוענים אותו ומפעילים את הפונקציה שהוא מחזיר. הפרמטרים הם מספר שחקנים, משך מרבי, והאם לעצור אחרי בדיקת האיסוף. פרמטר רביעי, LoopSmoke, בודק יציאות חוזרות במצב דליל בלי להמתין לסגירת הסיבוב; מתחילים בו מאיסוף פריט אחד בלבד. הגבולות הם 1–8 שחקנים ועד 900 שניות למדידה, בתוספת watchdog מוגבל של 110 שניות; בבדיקת מעבר שאורכה קצר מכך מוקצות לפחות 220 שניות לפני תוספת זו. קוראים את התוצאה מתוך המאפיין GrabItQAResult של הפרויקט.

הכלי מציב זמנית את שני runners במקומות המתאימים, מפעיל ExecuteMultiplayerTestAsync ומסיר אותם בסיום. מופעי Studio הנוספים שייכים לשרת ולשחקני הבדיקה. EndTest סוגר אותם ומשאיר את עורך הפרויקט פתוח. יש timeout שמגביל את הבדיקה. אין לשמור את המשחק בזמן שתסריטי הבדיקה הזמניים מחוברים.

הגרסה המותקנת של JestRobloxRunner, מספר 0.4.6, בודקת כל קריאה למערכת הבדיקות. המקור שמצורף ל־CLI שלה מתעד ויתור על הרצה כשכבר קיים המאפיין JestRobloxRunClaimed. הכלי משתמש בתיאום הזה רק לזמן הבדיקה ומשחזר את הערך הקודם. הוא אינו משנה או מכבה את ה־plugin, אינו מפעיל LoadString, אינו משנה הרשאות API ואינו כותב ל־DataStore.

אפשר להעביר פרמטר חמישי RoutePlan, כמחרוזת JSON של שלוש רשימות מסעות מזהי חפצים. מודול routes מרכז רק את המסעות והרכישות ומשתמש בהליכה ובאיסוף של client; אינו runner נוסף. אובייקט עם stages ו־finishCosmetics מפעיל צבירה עד כל העיצובים ומחייב משך 900. פרמטר שישי staggered מתחיל ב־client אחד ומוסיף את השאר אחרי active; אין לשלבו במסע solo. הוא משתמש באותו כלי ומחייב משך של לפחות 450 שניות. המסלולים מגיעים מקובץ חישוב האיזון; נרשמים זמן שרת, פריטים ותגמול בכל הפקדה. במסלול יחיד נבדקים גם Next אחרי ריקון שלב 1 וסיכום עד מקצה חדש. אין בכך בדיקת קלט אנושי, ומסלול שאזל זמנו נכשל במקום לשנות את זמן המשחק.

מה נבדק

כל שחקן מתחיל בלי התקדמות, ממתין לטעינת הדמות והולך במפה באמצעות Humanoid:MoveTo. בקשות האיסוף נשלחות דרך RemoteEvent הרגיל של המשחק. נבדקים חפצים אישיים, שמונה פריטים במשקל 10, תגמול 18 והאטה לפי משקל, ניסיון חוזר, הפקדה, יציאה נוספת, אובדן מטען בסגירה, שמירת המטבעות שכבר הופקדו, מעבר לשלב 2 והמשך משחק. בסיום בדיקה מלאה שחקן בדיקה אחד יוצא; האחרים מאשרים שהיתרה בממשק לא התאפסה.

זו אינה בדיקת מחוות touch או קלט מקלדת. אלה נבדקים בנפרד. ערוץ QA קיים רק בזמן הבדיקה ואינו מעניק מטבעות. ההמתנה למצב שרת עדכני נחוצה גם בכלי עצמו: הגעה למיקום אינה אומרת שהבחירה החדשה כבר הגיעה דרך הרשת.

מדידת ביצועים

בהרצה של לפחות 600 שניות המדידה מתחילה רק כאשר המאפיין MeasureFrames בערוץ QA של שרת הבדיקה מקבל true. לפני כן מגדירים ומאמתים רזולוציה בפועל. מעבר מ־false אל true מאפס את המדדים. כל שחקן אוסף 600 שניות של RenderStepped, מספר frames ומספר frames שאורכם מעל 1/30 שנייה. בנוסף נמדדות דגימות באורך שנייה לפחות, מינימום FPS ומספר דגימות מתחת ל־30 FPS; אחר כך הוא מסיים את היציאה הנוכחית. הבדיקה מוגבלת בזמן גם אם המדידה לא הופעלה.

מתעדים רזולוציה, איכות גרפיקה בפועל, חומרת המחשב, גרסת Studio, מספר שחקנים והפרעות מדידה כמו צילום או debugging. תוצאה מהירה במצב Automatic אינה אישור לדרגת גרפיקה 5. הדמיית נייד על Mac אינה בדיקת חומרה של טלפון.

שחזור בדיקת שני מגעים — אומת בתאריך 24/10/2026

מפעילים הדמיית טלפון ב־Solo באותו חלון, וממקמים שחקן חדש ליד חפץ מתאים. MoveTo מותר רק להכנת מיקומו. רושמים TouchStarted, TouchMoved, TouchEnded, את מיקומי שני InputObjects, את MoveDirection של הדמות ואת מצב המטען מהשרת. ההפעלה עצמה נעשית רק בקלט המובנה דרך Studio MCP, בלי קריאה ישירה לאיסוף או הפעלת signal.

מחזיקים Alt ומתחילים מחווה באזור שאינו Collect. כדי להביא את שני המגעים למיקומים הרצויים, מבצעים תחילה pan עם Alt+Shift, ואחריו pinch או סיבוב עם Alt בלבד. השילוב מתועד בתוך Device Simulator. יעד אחד הוא מרכז Collect והיעד השני בתוך אזור ה־joystick. משחררים עכבר ומשאירים Alt מוחזק; כך מיקום הזוג נשמר למחווה הבאה.

מתחילים מחווה חדשה על Collect, עם המגע השני על joystick. מזיזים 14 פיקסלים בתוך הכפתור ומשחררים בתוכו. המגע הנגדי זז באזור התנועה. הבדיקה עוברת רק אם קיימים שני InputObjects נפרדים בו־זמנית, הדמות נעה בזמן Collect.Activated ומצב השרת מתקדם ממטען ריק לחפץ אחד בלבד. בסיום משחררים את כל הקלט ומסירים את חיבורי התצפית. תוצאת שני פרופילי הטלפון נשמרה בתוך הראיות.

אלה מגעים נפרדים שמסלוליהם מחוברים בהדמיה. ההצלחה אינה בדיקת נוחות במכשיר פיזי או תוצאה של playtest אנושי.

בדיקת שמירה אמיתית בענן

נדרש אישור אדם להפעלת Studio API Services במשחק המאומת. ב־Studio רגיל אין שמירה בענן. מאפיין GrabItQACloudRun בתוך ServerStorage, עם מזהה הרצה באורך 1–20 תווים באנגלית, ספרות, קו תחתון או מקף, מפעיל את DataStore הנפרד GrabItV1_QA_Verification. במשחק חי המאפיין אינו משפיע.

ל־Team Create הוכן מקומית מסלול TestArgs זמני לפי הגדרת השמירה; סנכרונו ואתחולו אומתו בבדיקת שחקן מלאה ב־27/10/2026. אין להוסיף סימון QA ב־Edit שעלול להישמר אוטומטית, ואדם אישר במפורש סנכרון לעותק הפיתוח בענן לצורך QA, ללא Publish או שינוי גישה. בדיקת ה־backend בענן והפער שנותר אינם תחליף לתרחיש השחקן שלהלן.

בודקים שני שרתי Solo עוקבים באותו חלון: התחלה ריקה, הפקדה ו־Saved, סיום ושחרור נעילה, ואז כניסה מחדש והמשך הפקדה. מודול cloud-check מבצע קריאה ללא cache ומאמת מטבעות, הדרכה ונעילה צפויים. הקריאה עצמה אינה משנה נתונים. בסיום מסירים רק את מפתח ההרצה שנוצר, מוודאים מחיקה, מסירים את המאפיין ומשחזרים מצב Studio רגיל. אין לשמור קובץ או לפרסם כאשר המאפיין הזמני קיים. תוצאות ההרצה המאומתת.

חיבור QA לשחקן ב־Team Create

לאחר בדיקת backend בענן נותר חיבור שחקן מלא. מרחיבים את StorageMode הקיים בארגומנט TestArgs אופציונלי ומעבירים אליו את GetTestArgs בצד השרת, רק ב־Studio וב־pcall. בדיקת StorageMode הקיימת נכשלת על המסלול החדש לפני המימוש; לאחריו היא מאמתת marker מדויק, גבולות runId, קדימות הסימון הקיים והתעלמות מוחלטת במשחק חי.

אחרי source sync ו־code review מפעילים ExecutePlayModeAsync עם runId חדש שנבדק ריק מראש, בלי שינוי מאפייני Edit או שכפול runners לשם. מאמתים קבלת מטבעות במשחק, קנייה ליתרת אפס, בחירה, סיום וכניסה חדשה עם אותם נתונים. Source משתנה בקבצים מקומיים וב־Rojo בלבד. אין פרסום, הרשאות חדשות או גישה ל־store של production.
