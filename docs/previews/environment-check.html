הגדרות הפרויקט והרצת tests

  • נוספו קובצי rokit.toml, stylua.toml ו־selene.toml. הם משתמשים בעותקי הכלים שכבר מותקנים; לא הותקנו כלים חדשים.
  • הקובץ roblox.yml הוא עותק מקומי של הגדרות ה־lint שכבר היו במחשב. הבדיקה אינה תלויה בהורדה אוטומטית שלהן. לא אומתה התאמה מלאה של כל הגדרה לכל API בגרסת Studio הנוכחית.
  • נשמר פרויקט Rojo מבודד תחת tools/environment-check, כולל שני מודולי בדיקה. גם יצירת קובץ מקום ממנו עברה.
  • הורץ test עם assert המובנה בשפה: הוא נכשל כשהקובץ המקומי הכיל ערך 1, ולאחר שינוי לערך 2 עבר בלי לשנות את ה־test. ההצלחה אומתה גם בצד Server וגם בצד Client, ונקראה מתוך Output.
  • ה־test מאמת את שרשרת הקובץ המקומי, סנכרון Rojo והרצת מודול ב־Studio. אין צורך בחבילת tests חיצונית לבדיקה הזאת. הוא אינו מכסה התנהגות משחק.
  • בוצע code review בשיחה הראשית לשני מודולי הבדיקה ולהיקף הסנכרון; לא נמצאה בעיה חוסמת. פרויקט הבדיקה שומר על אובייקטים שאינם מנוהלים על ידו ומנהל רק תיקייה ייעודית.

מגבלות ונושאים שאינם חלק מבדיקת התשתית הבסיסית

  • Wally זמין בהפעלה ישירה אך אינו נדרש כרגע: לא נבחרו חבילות חיצוניות ולא נוסף לפרויקט dependency עליו.
  • העותק הישן של Wally 0.3.2 נכשל בגלל חוסר התאמה לסוג המעבד. העותק החדש שצוין בטבלה פועל.
  • לא נמצאו הפקודות Lune, luau או luau-analyze. לא הוחלט שכולן נחוצות.
  • לא נבדקו כמה שחקנים בו־זמנית או touch controls.
  • במהלך הפעלת מקום הבדיקה הופיעה שגיאת טעינת asset שמספרו 203785492: סוג ה־asset אינו תואם לסוג שהתבקש. מקור השגיאה לא אובחן. בדיקות החיבור והפקודות עברו למרות השגיאה.

מסקנה: כלי העבודה הבסיסיים אומתו מקצה לקצה: קבצים מקומיים, Rojo, Studio MCP, הרצת test שנכשל ואז עובר, עיצוב קוד ו־lint. זו סביבת בסיס עובדת לתכנון הפיתוח. tests של המשחק, בדיקות מרובות שחקנים ובדיקות controls יוגדרו לפי העבודה שתאושר. לא נכתב gameplay ולא הוכן plan.
