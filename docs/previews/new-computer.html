העברת הפרויקט למחשב אחר

עודכן בתאריך 26/10/2026: הרפרנסים הדרושים למחקר ולבדיקות נכללים כעת ב־Git באישור אדם. Studio ו־Rojo לא הופעלו, ולא בוצע push.

הפיתוח ובדיקות המשחק נשארים בהפסקה. מטרת המסמך היא להעביר את העבודה וההנחיות, ואז להכין את המחשב החדש לחידוש מורשה. ההתקנה במחשב השני עדיין לא בוצעה; הוראות הכלים נבדקו מול המקורות הרשמיים.

מה נמצא בבדיקה

רכיב מה נשמר ומה צריך לעשות
העבודה הנוכחית נמצאת בתוך branch בשם codex/v1-improvements. בבדיקת ההעברה המקורית נמצא ב־GitHub רק main בקומיט הראשון, 7515300. הממצא היסטורי ואינו בדיקת מצב GitHub לאחר הדחיפות של אדם. יש לדחוף ולמשוך גם את קומיט הרפרנסים החדש. דחיפת main בלבד לא תעביר את העבודה
החוקים וההנחיות AGENTS וכל תשעת קובצי rules נמצאים במעקב. כלל הכיבוי של Rojo נשמר בקומיט 173e7d4
המיומנויות כל 14 המיומנויות המקומיות ו־72 הקבצים שלהן נמצאים במעקב בתוך .agents. אין קישור לתיקייה חיצונית שצריך לשחזר
hooks שני הקבצים בתוך .codex/hooks נמצאים במעקב. ה־hook המיובא אינו פעיל ואינו דרוש להפעלת הפרויקט; אין להפעילו במחשב החדש
קוד, דגמים וכלי פיתוח המקורות, הדגמים, קובצי Rojo, הגדרות StyLua ו־Selene וקובץ גרסאות הכלים נמצאים במעקב. כל נתיבי המקור בקובצי Rojo קיימים ונכללים ב־Git
קובץ העבודה build/GrabItV1_DesktopMobile.rbxlx נמצא במעקב. הוא מכיל גם עותקים ישנים של scripts; קבצי src הם המקור העדכני. לפני Play במחשב החדש חייבים לאמת סנכרון, ולא לבנות מחדש מעל השמירה
שמירות ידניות שני המקוריים בשורש זהים לפי SHA256. באישור אדם נשמר עותק יחיד בתוך backups/manual/2026-10-26/GrabItV1_DesktopMobile.rbxl והוא מגיע דרך Git. המקוריים וקובץ העבודה לא שונו; אין צורך בהעתקה נפרדת
רפרנסים 19 קובצי המחקר וראיות הבדיקה בתוך references נכללים כעת ב־Git. תמונות המתחרים, הנתונים, האינדקסים והחתימות מגיעים עם clone או pull של branch העבודה; אין צורך להעתיקם בנפרד
הגדרות MCP חיבור Roblox_Studio נמצא בהגדרות המשתמש של המחשב, ולא בפרויקט. צריך להגדירו במחשב החדש. אין בפרויקט .codex/config.toml
מצב ההמשך נקודת העצירה, דוחות הבדיקה וראיות הצילום נשמרים ב־Git. אין להניח שהיסטוריית השיחה עצמה עוברת באמצעות Git

כל ה־branches המקומיים הקיימים כלולים בהיסטוריה של branch העבודה. לצורך העברת המצב הנוכחי מספיק לדחוף אותו; אין צורך למזג לתוך main או לדחוף את כל ה־branches.

במחשב הנוכחי, לפני המעבר

  1. לדחוף את branch העבודה. לאחר קומיטי ההעברה, אדם מבצע push של codex/v1-improvements אל origin ומוודא שהוא מופיע ב־GitHub. השיחה אינה מבצעת push.
  2. לוודא שקומיט הגיבוי נדחף. הרפרנסים ועותק הגיבוי הידני מגיעים כעת דרך Git. רשימת הקבצים והחתימות מאפשרת לוודא שהם הגיעו שלמים. אין צורך להעתיק את שתי השמירות שבשורש בנפרד.
  3. לשמור את המחשב הישן עד שההעברה אומתה. קובצי הגיבוי לא נפתחו במהלך הבדיקה, ולכן לא נקבע שהתוכן הידני שלהם זהה לתוכן קובץ העבודה. שמירה לענן אינה מחליפה את העברת המקורות והרפרנסים.

עותק הגיבוי שנכלל ב־Git:

backups/manual/2026-10-26/GrabItV1_DesktopMobile.rbxl

תיעוד הגיבוי מפרט את מקורו ואת מגבלות השימוש בו. אין לפתוח אותו במקום קובץ העבודה בדרך רגילה.

sourcemap.json הוא קובץ מיפוי שנוצר מקומית. אינו מקור הקוד ואינו נדרש להעברה. קובצי .DS_Store, שרתי תצוגה, תהליכים ומצב חיבור אינם הגדרות פרויקט להעברה.

במחשב החדש — צעדים לפי הסדר

  1. להתקין Git ולהתחבר ל־GitHub. לבחור Mac או Windows מתוך אתר Git. לוודא שלחשבון יש גישה למאגר. אפשר לבצע clone דרך ממשק Git קיים; התחברות לחשבון אינה עוברת יחד עם התיקייה.
  2. להוריד דווקא את branch העבודה. לבצע clone של המאגר ולבחור codex/v1-improvements. אפשר לבחור שם תיקייה פשוט כמו GrabItRun; אין דרישה לשחזר את נתיב המשתמש מהמחשב הישן. הוראות clone הרשמיות מסבירות גם שימוש בממשק גרפי.
  3. לוודא שהחומר הגיע. לבדוק שתיקיית references וקובץ הגיבוי המתועד קיימים אחרי המשיכה. אין צורך בשתי השמירות המקוריות שבשורש המחשב הישן. לא להחליף את קובץ build בגיבוי; הוא מיועד לשחזור בלבד.
  4. להתקין את אפליקציית OpenAI שבה תעבוד. להיכנס לאותו חשבון ולפתוח את תיקיית הפרויקט במצב Codex. להשתמש בהוראות האפליקציה הרשמיות. לתת גישה לתיקיית הפרויקט, ולוודא שנקראו AGENTS ו־rules ושהמיומנויות המקומיות מופיעות. לפי תיעוד המיומנויות, Codex סורק את .agents/skills מתוך המאגר. אין צורך להתקין את 14 המיומנויות שוב ברמת המשתמש.
  5. להתקין Roblox Studio. להוריד מתוך ההוראות הרשמיות ולהיכנס לאותו חשבון Roblox. בשלב ההכנה אין צורך להפעיל משחק. האימות של החיבור והסנכרון בהמשך ייעשה רק כשהפרויקט הזה הוא יעד העבודה המורשה.
  6. להתקין Rokit. לבחור את הוראות Mac או Windows בתוך המאגר הרשמי, ואז לפתוח Terminal חדש. מתוך תיקיית הפרויקט להריץ rokit install. הקובץ rokit.toml יקבע את הגרסאות: Rojo מספר 7.7.1, StyLua מספר 2.5.2 ו־Selene מספר 0.32.0. אין להריץ rokit update או rokit init לצורך המעבר; אין צורך לשנות את הגרסאות.
  7. להתקין את Rojo plugin. אחרי התקנת Studio והכלים, להריץ rojo plugin install מתוך תיקיית הפרויקט, או להתקין את plugin הרשמי התואם ל־Rojo 7. ה־CLI וה־plugin הם שני רכיבים נפרדים, לפי הוראות Rojo. התקנת plugin אינה הפעלת שרת סנכרון.
  8. להגדיר מחדש את Studio MCP. כשהעבודה במשחק הזה תחודש, לפתוח רק את קובץ העבודה שלו בחלון Studio אחד. ב־Assistant לפתוח Manage MCP Servers, להפעיל Enable Studio as MCP server ולבחור את לקוח Codex בתוך Quick connect. אם הוא אינו מופיע, לפעול לפי Setup instructions ולא להעתיק נתיב Mac למחשב Windows. נדרש חיווי של לקוח מחובר; מתג מסומן לבדו אינו מספיק. הוראות MCP הרשמיות.
  9. לבצע אימות קצר לפני המשך הפיתוח. לבקש מהשיחה החדשה לקרוא תחילה את מסמך המעבר ואת נקודת העצירה. לוודא שזהות המשחק היא place מספר 106986292768692 ו־universe מספר 10772701508, ושמבנה הפרויקט תואם. לא להשתמש במשחק אחר לצורך בדיקת החיבור. לאחר אישור חידוש העבודה מפעילים שרת Rojo אחד בפורט 34872, מחברים אליו את החלון הנכון ומאמתים שהקוד העדכני מתוך src הגיע אליו לפני Play. לא יוצרים מקום חדש ולא מריצים build מעל קובץ העבודה.
  10. להמשיך מנקודת העצירה. שער התצוגה ויתר הקבלה עדיין לא הסתיימו. כלי QA ההיסטוריים מחייבים התאמה לפני שימוש, כמפורט בנקודת העצירה. בכל עצירה מכבים את שרת Rojo של הפרויקט ומאמתים שהוא נסגר.

פקודות לשימוש בזמן ההעברה בלבד

כל קבוצה מיועדת למחשב המצוין מעליה. אין להריץ את כולן ברצף במחשב אחד. פקודות התקנת Rokit תלויות במערכת ההפעלה ונמצאות בקישור בשלב 6. הפקודות שלהלן לא הופעלו במסגרת הכנת המסמך.

# Current computer: run from the existing repository; Adam pushes.
git push --set-upstream origin codex/v1-improvements

# New computer: run from the parent folder chosen for the project.
git clone --branch codex/v1-improvements https://github.com/adamshmuel/Grab-It---Run-.git GrabItRun
cd GrabItRun
git branch --show-current
git log -1 --oneline

# New computer: after installing Studio and Rokit.
rokit install
rojo --version
stylua --version
selene --version
rojo plugin install

# Only after authorized resumption in the verified game window.
rojo serve default.project.json --port 34872

אין חובה להתקין כרגע VS Code, Node.js, Python, Wally או JestRobloxRunner כדי להפעיל את קוד המשחק והבדיקות המקומיות הקיימות. קובצי הבדיקה משתמשים ב־assertions בתוך Studio; ה־hook המיובא אינו פעיל. אם עבודה עתידית תדרוש כלי נוסף, מאמתים צורך ותאימות לפני התקנתו. לקריאת המסמכים אפשר לפתוח את קובצי HTML השמורים בתוך docs/previews בדפדפן, גם בלי שרת localhost הישן.

הגדרות שנשארות ברמת המחשב

חיבור MCP המקומי הקיים מפנה לקובץ StudioMCP בתוך התקנת Studio במחשב Mac. אין להעתיק את כל הגדרות המשתמש של Codex או נתיבי יישומים למחשב השני. רושמים מחדש את חיבור Studio לפי מערכת ההפעלה. תיעוד ההגדרות של OpenAI מבדיל בין הגדרות משתמש לבין הגדרות פרויקט.

התחברות לחשבונות, אישורי מערכת, בחירת מודל, הגדרות אפליקציה וחיבורים של plugins חיצוניים אינם חלק מ־Git. מאמתים אותם במחשב החדש לפי הצורך. אין להעביר סיסמאות או מפתחות פרטיים אל המאגר. אין צורך בהרשאות שליטה כללית במחשב לשם פעולות Studio שה־MCP מספק. אישור API Services הקודם מוגבל למשחק הזה; אינו היתר לשנות סביבה או נתונים של משחק אחר.

מתי ההעברה הושלמה

  • branch העבודה וכל קומיטי ההעברה הגיעו למחשב החדש; החוקים, 14 המיומנויות וקובץ העבודה קיימים.
  • עותק הגיבוי המתועד והרפרנסים הגיעו באמצעות Git ונבדקו מול החתימות. התמונות נפתחות מתוך מסמכי המחקר. שני המקוריים בשורש אינם נדרשים במחשב החדש.
  • הכלים נמצאו בגרסאות המוגדרות, והאפליקציה קוראת את הוראות הפרויקט.
  • בחידוש המורשה אומתו זהות המשחק, חיבור MCP וסנכרון Rojo בפועל. עד אז הסביבה החדשה מוכנה להתקנה, אך אינה סביבה שעברה אימות הרצה.
